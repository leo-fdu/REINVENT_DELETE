# evaluation/docking — AutoDock Vina docking module

Docks the molecules generated by REINVENT4 (`reinvent`) and DELETE (`delete`)
into the 16 real-world targets and produces a comparable per-molecule score
table.

Data flow (per AGENTS.md):

```
generated SMILES table (upstream adapter output)
        │
        ▼
SMILES ──RDKit ETKDGv3 + MMFF──▶ 3D conformer ──Meeko──▶ ligand PDBQT
        │                                                 │
receptor_out.pdb ──Meeko──▶ receptor PDBQT ──▶ AutoDock Vina ──▶ vina_score
crystal.mol2 ──box_utils──▶ grid box (frozen per target) ──┘
```

Module layout:

| Path | Purpose |
|---|---|
| `box_utils.py` | pure-Python `.mol2` parser + grid-box derivation (no RDKit needed) |
| `prepare_receptors.py` | one-time receptor PDB→PDBQT conversion + per-target config freezing |
| `run_docking.py` | main pipeline: SMILES CSV → docking → 5-column score CSV |
| `configs/<target>.json` | frozen grid box + shared Vina parameters per target (versioned) |
| `prepared/<target>/receptor.pdbqt` | derived receptor PDBQT (regenerable, not versioned) |
| `results/` | run outputs (derived, not versioned) |

## 1. Environment setup (Linux server)

All dependencies are on conda-forge:

```bash
cd <repo root>
conda env create -f evaluation/docking/environment.yml
conda activate rd-docking
```

This installs `python=3.11`, `rdkit`, `meeko>=0.6` (provides
`mk_prepare_receptor.py`), `vina>=1.2.5` (provides both the `vina` binary and
the Python bindings), `numpy` and `pytest`.

If your conda cannot solve the environment, the pip fallback inside any
Python 3.11 env with RDKit and numpy works too:

```bash
pip install "meeko>=0.6" "vina>=1.2.5"
```

Quick check:

```bash
mk_prepare_receptor.py --help | head -3
python -c "import rdkit, meeko, vina; print(rdkit.__version__, meeko.__version__, vina.__version__)"
```

## 2. Step 1 — prepare receptors (once)

```bash
python evaluation/docking/prepare_receptors.py
```

For each of the 16 targets in `real-world_dataset/` this writes:

- `evaluation/docking/prepared/<target>/receptor.pdbqt` — receptor converted
  by Meeko's `mk_prepare_receptor.py` from
  `prepared/<target>/receptor_sanitized.pdb`. Two deterministic policies apply:
  - **ALA relabeling** (`receptor_sanitized.log`): several source receptors
    contain residues truncated to backbone+CB (e.g. CDK2's G-loop, JAK2's
    C-lobe). Dropping them would punch holes in the pocket, so they are
    relabeled to ALA — atom records and coordinates stay byte-identical, and
    the receptor keeps exactly the atoms PLANET saw during generation.
  - **Meeko flags** (`receptor.meeko.log`): `--default_altloc A` resolves
    alternate locations present in several original receptors;
    `--allow_bad_res` remains only as a last-resort guard — any residue it
    drops is logged and must be verified to be far from the grid box (JAK2's
    two PTR phosphotyrosine HETATM records are dropped this way; PLANET
    ignores HETATM records as well);
- `evaluation/docking/configs/<target>.json` — the frozen fairness contract:
  - `box.center` = heavy-atom centroid of `crystal.mol2`
  - `box.size` = crystal-ligand bounding box + 8 Å padding on **each** side
    (extent + 16 Å per axis)
  - `vina`: `scoring=vina`, `exhaustiveness=16`, `num_modes=1`, `seed=42`

Useful options: `--targets adrb1 cdk2` (subset), `--box-only` (rewrite only
the JSON configs, skip receptor conversion).

### Corrected targets: JAK2 and DRD3

The original upstream receptors/pockets for JAK2 and DRD3 were found to be
wrong during the PLANET RL workflow audit (JAK2's `receptor_out.pdb` is a
JNK3/mixed/truncated input; DRD3's design-ligand centroid misses the
crystallographic orthosteric pocket). See
`configs/manual_planet_rl/README.md` for the full analysis.

When `configs/manual_planet_rl/target_inputs.json` is present (it is
versioned in this repo), `prepare_receptors.py` prepares these two targets
from the **same traceable corrections** so the Vina numbers stay comparable
with the generation experiment:

- receptor: the extracted author chain (`src/planet_target_inputs.py`,
  identical code and source hashes as the RL workflow) written to
  `evaluation/docking/prepared/<target>/receptor.pdb`, then converted to
  PDBQT. The original `receptor_out.pdb` files are retained untouched.
- grid box: derived from the pocket-reference crystallographic ligand
  (JAK2: 3LPB NVB A/1133; DRD3: 3PBL ETQ A/1200) with the same 8 Å padding
  policy. For JAK2 the reference coordinates are identical to the design
  `crystal.mol2`, so its box numbers do not change; DRD3's box moves to the
  ETQ pocket (center `[0.085, -14.828, 10.432]`).
- provenance: each corrected config carries an `input_correction` block
  (source PDB, SHA-256, chain, reference residue, reason). Source hashes are
  re-validated on every prepare run; any change fails loudly.

All other 14 targets keep using `receptor_out.pdb` + `crystal.mol2` as
before.

## 3. Step 2 — run docking

```bash
python evaluation/docking/run_docking.py \
    --input <smiles_table.csv> \
    --out evaluation/docking/results/run1/docking_scores.csv \
    --n-jobs 8
```

### Input contract

One CSV covering all targets and both models, with at least the columns
(extra columns are ignored):

| column | meaning |
|---|---|
| `target` | target directory name, e.g. `adrb1` (must have `configs/<target>.json`) |
| `method` | `reinvent` or `delete` |
| `smiles` | canonical SMILES of the generated molecule |

DELETE's raw output is **not** SMILES; convert it upstream first (that adapter
is a separate module). The identical table must feed both the docking and the
descriptor modules.

### Output

`<out>` — exactly five columns:

```
molecule_id,method,target,smiles,vina_score
```

- `molecule_id`: 1-based sequential number within each `(target, method)`
  group, following input row order;
- `vina_score`: best-pose Vina energy (kcal/mol, lower = better); empty when
  the molecule failed.

Side files written next to `<out>`:

- `<out_stem>_errors.csv` — one row per failed molecule with the exception
  message (only created when failures occurred);
- `<out_stem>_summary.csv` — per `(target, method)` statistics: molecule
  count, success/failure counts, best/mean/median `vina_score`.

Other options: `--config-dir` (default `evaluation/docking/configs`),
`--limit N` (dock at most N molecules per target — for smoke tests).

### Failure handling

A molecule that fails SMILES parsing, 3D embedding, Meeko preparation or the
docking itself never aborts the run: its `vina_score` is left empty and the
reason is logged in the errors file. Multi-fragment SMILES (salts) are docked
as their largest fragment; the `smiles` column in the output is always the
unmodified input string.

## 4. Reproducibility and fairness

- Grid boxes and Vina parameters are frozen in the versioned
  `configs/*.json` files and are identical for both models — any difference
  in scores comes from the generators, not the evaluation path.
- Ligand 3D generation: RDKit ETKDGv3 with `randomSeed=42` (fallback: random
  coordinates), then MMFF minimisation (UFF fallback).
- Vina runs with fixed `seed=42` and `cpu=1` per worker, so scores are
  reproducible regardless of `--n-jobs`.
- Raw inputs are never modified; all derived artefacts live under
  `prepared/` and `results/`.

## 5. Smoke test (recommended after setup on the server)

```bash
printf 'target,method,smiles\nadrb1,reinvent,CCOc1ccc2nc(N)nc(-c3ccco3)c2c1\nadrb1,delete,CN1CCN(c2ccc(N)cc2)CC1\n' > /tmp/smoke.csv
python evaluation/docking/run_docking.py --input /tmp/smoke.csv --out /tmp/smoke_out/scores.csv
cat /tmp/smoke_out/scores.csv
```

Expected: two rows with finite negative `vina_score` values and no errors
file. Unit tests for the pure-Python box logic (runnable without RDKit):

```bash
python -m pytest tests/docking/ -v
```
